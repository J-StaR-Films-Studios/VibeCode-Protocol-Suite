# The working record

Keep one authoritative calendar or manifest in the project. Exports, packs, contact sheets and screenshots support it. Do not let an older helper overwrite new platform status or the selected design.

| Fact | Record |
| --- | --- |
| Identity | Stable post ID, destination and content type |
| Source | Original path or URL, source identity and excerpt times |
| Copy | Current caption and verified factual basis |
| Creative choice | Selected design, feedback and applicable approval |
| Media | Version, derivative paths and any rejected versions |
| Review | Checks performed, observed defects and unresolved limits |
| Intent | Publication timestamp, timezone and cadence |
| External state | Draft, scheduled, published, processing, failed or unverified, with the platform's media version |
| Evidence | Platform ID or URL when available, verified date and useful screenshot |
| Next action | Reuse draft, replace media, schedule when eligible, obtain specific approval or resolve access |

Use the simplest structure that preserves these distinctions. A modest content batch does not require a database or framework.

## Version reconciliation

Approval of design B does not change a previously scheduled design A. Track local approval and platform version separately until replacement is saved and verified.

Keep provenance for rejected versions but give publishing one unambiguous current-media selection. A record that says ready while pointing at rejected files is unsafe. Do not infer approval from folder names.

Preserve existing post identity and intended date when replacing media. Inspect saved state before recording success. Synchronize caption edits so future runs do not restore old wording.

## Reconcile before retries

Match live entries by platform IDs where available. Caption, thumbnail and date can help when an ID is absent. Caption equality alone cannot distinguish an old scheduled version from a replacement draft.

Load the entire relevant list, including scrolling or pagination. Ten visible posts do not prove twenty-eight drafts exist. Inspect ambiguous entries before uploading another copy.

Link previews may omit URLs from headings. A title match identifies a candidate; inspect the post or editor before claiming the destination URL is correct.

## Portable deliverables

Export from the authoritative record after confirmed changes. Retain selected-media paths. Verify referenced files exist and pack references resolve inside the archive. Validate completed ZIPs when requested.

Clearly label rejected media that remains in a pack. Prefer explicit current-media selection over asking the next agent to infer it from several exports.

Report collection counts separately from earlier or unrelated posts. Include actual states, remaining eligible actions and known review limits. Pending drafts are not scheduled posts.
