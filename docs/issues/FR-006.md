# FR-006: Compact Takomi Runtime and Policy Packs

## Labels

takomi-context-manager, mus

## User Story

As a Pi/Takomi user or agent, I want compact takomi runtime and policy packs, so that context is loaded only when useful without losing capability.

## Proposed Solution

Keep complete applicable model-routing guidance available before model choice on every turn. Remove only an exact duplicate runtime policy copy when the context manager supplies the same full policy. Preserve role/workflow instructions, optional tool guidance, and provider-qualified registry IDs.

## Implementation Flow

- Re-resolve project/global/bundled routing policy between turns
- Supply the full resolved policy before the model chooses a delegate
- Pause `takomi_subagent` when policy is missing unless the user approves session-only defaults
- Keep other policy packs available through explicit manifest/load tools

## Technical Approach

Use a Pi TypeScript extension where possible. Prefer `before_agent_start` for prompt shaping, registered tools for progressive skill access, and diagnostics for observability. Avoid forking Pi internals unless extension hooks prove insufficient.

## Key Considerations

- Preserve strong tool guidance.
- Keep always-on context minimal.
- Make behavior observable and testable.
- Markdown guidance and role defaults remain advisory; only explicit `approvedModels` settings create a strict allowlist.
- Missing-policy, allowlist, and runtime-disable gates cover `takomi_subagent`, not arbitrary tools or all model choices.
- Child fresh/replaced prompts and task-specific skills are separate from parent prompt rewriting. Native tool exposure defaults are unchanged.
- Coexist with Pi/Takomi current resource loading where possible.

## Acceptance Criteria

- [x] Small tasks are not over-orchestrated
- [x] Full policy is available before delegation choice across repeated, changed-policy turns; missing policy pauses the supported entrypoint
- [x] Workflow packs load only when selected
