# FR-005: Context Router Candidate Surfacing

## Labels

takomi-context-manager, mus

## User Story

As a Pi/Takomi user or agent, I want context router candidate surfacing, so that context is loaded only when useful without losing capability.

## Proposed Solution

Suggest likely skills without injecting full content. Score only the current user prompt against skill names and up to 50 description words. Semantic, conversation, and project-aware retrieval remain proposals.

## Implementation Flow

- Recognize explicit skill names with identifier boundaries
- Match name and description keywords as whole normalized tokens
- Inject up to five candidates by default; keep configurable medium/high thresholds of 40/100
- Record reasons for diagnostics

## Technical Approach

Use a Pi TypeScript extension where possible. Prefer `before_agent_start` for prompt shaping, registered tools for progressive skill access, and diagnostics for observability. Avoid forking Pi internals unless extension hooks prove insufficient.

## Key Considerations

- Preserve strong tool guidance.
- Keep always-on context minimal.
- Make behavior observable and testable.
- Coexist with Pi/Takomi current resource loading where possible.

## Acceptance Criteria

- [x] Exact named skills remain discoverable; longer-word substrings alone do not create candidates
- [x] Low-confidence prompts do not add noise
- [x] Candidates are names plus action hint only

## Verification Notes

`node --experimental-specifier-resolution=node scripts/test-context-manager-renderers.js` covers exact names, lexical false positives, whole-word triggers, vague prompts, candidate caps, and configured thresholds. Candidate hints are advisory, not guaranteed semantic recall.
