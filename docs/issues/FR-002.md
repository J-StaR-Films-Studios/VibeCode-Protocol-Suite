# FR-002: Skill Index

## Labels

takomi-context-manager, mus

## User Story

As a Pi/Takomi user or agent, I want skill index, so that context is loaded only when useful without losing capability.

## Proposed Solution

Show the available count and up to five candidate names by default. Expose all names through `skill_index`; `all-names` is an optional display mode.

## Implementation Flow

- Discover loaded skills
- Render count plus candidate hints by default
- Return all names on explicit `skill_index` requests
- Compact descriptions only in recognized Pi skill-catalog XML; preserve unknown shapes and report compaction unavailable

## Technical Approach

Use a Pi TypeScript extension where possible. Prefer `before_agent_start` for prompt shaping, registered tools for progressive skill access, and diagnostics for observability. Avoid forking Pi internals unless extension hooks prove insufficient.

## Key Considerations

- Preserve strong tool guidance.
- Keep always-on context minimal.
- Make behavior observable and testable.
- Coexist with Pi/Takomi current resource loading where possible.

## Acceptance Criteria

- [x] Agent sees candidate names and can request the full names-only index
- [x] Recognized catalog descriptions are removed; unknown catalog instructions remain intact
- [x] Index updates after reload

## Verification Notes

`node --experimental-specifier-resolution=node scripts/test-context-manager-renderers.js` covers native Pi 0.99.1 XML, unknown shapes, explicit discovery, and retained candidate defaults with synthetic fixtures. It does not measure live efficiency.
