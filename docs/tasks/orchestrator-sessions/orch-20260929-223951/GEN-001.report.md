# GEN-001 read-only investigation
The worktree is clean. I made no changes and ran no tests or model calls. The packet had moved from `pending/` to `in-progress/`; I read it there, along with the session plan and finding register.
The main decision is about routing policy, not a missing loader. The context manager currently supplies the complete resolved policy before the model can choose a subagent model. Removing it without an equivalent pre-decision path would break that guarantee. I recommend keeping that behavior until a replacement is approved and tested.

## Proposed Build packets, after the decision checkpoint
1. **Prompt and routing contract.** Limit changes to `.pi/extensions/takomi-context-manager/{index,prompt-rewriter,config,prerequisite-gates}.ts` and, only where necessary, `.pi/extensions/takomi-runtime/index.ts`. First capture deterministic active/inactive runtime prompt fixtures with policy present, changed and missing. Remove proven duplicate text only after showing that complete applicable routing guidance reaches the model *before* its delegation choice. Preserve missing-policy pause, session approval and explicit-allowlist enforcement. Do not use a tool-call block-and-retry as a substitute for pre-decision guidance.
2. **Skill discovery and loading.** Limit changes to `context-router.ts`, `skill-registry.ts`, `skill-tools.ts` and `prompt-rewriter.ts` as justified by fixtures. Cover explicit names, ambiguous partial names, substring false positives, vague prompts, missing XML, and a large required `SKILL.md`. Acceptance: discovery remains available; unknown prompt sections survive; any loaded required pack remains complete and followable. Decide the names-only default before changing `config.ts`.
3. **Tool exposure, conditional packet.** First establish the installed 0.84.4 API contract from that package's documentation, declarations and examples. If native deferral requires an upgrade, prepare a separate upgrade and migration proposal rather than altering registrations now. Acceptance for any approved exposure change: essential discovery remains reachable in supported modes; `takomi_subagent` and its gates remain usable; tool schemas and active-set transitions have deterministic checks.
4. **Truthful reporting and documentation.** Update affected sections of `docs/Project_Requirements.md`, `docs/features/Takomi_Context_Manager.md`, FR-002/FR-005/FR-006 and context diagnostics only to distinguish shipped defaults, proposals, and measured character counts. A deterministic synthetic request inspection may report prompt, tool and history sizes separately. It must not label them billed tokens or task cost.
Use `scripts/test-context-manager-renderers.js` and the existing routing-safety tests as the focused starting point. No checks were run here: the worktree has no installed local `node_modules`, and Genesis forbids installs. I read the complete relevant **global 0.99.1** Pi extensions, skills, SDK, sessions and how-it-works docs, plus the dynamic-tools, truncation, skills-SDK and codemode/MCP examples. That reading supports conditional API options, not a pinned-version compatibility claim.
## Approval questions
1. Should FR-002's names-only *always-visible* index become the default, or should the requirement be corrected to the current count-plus-candidates default?
2. May Build change routing-policy loading semantics, provided complete applicable guidance is proved available before model selection, or should it only remove confirmed duplication under current semantics?
3. Is a Pi dependency upgrade in scope if native deferred exposure is unavailable in 0.84.4? Without approval, keep direct registrations.
4. Should oversized required skills retain unlimited complete loading, or should Build design an explicit complete-instructions continuation mechanism? Do not adopt silent truncation.
