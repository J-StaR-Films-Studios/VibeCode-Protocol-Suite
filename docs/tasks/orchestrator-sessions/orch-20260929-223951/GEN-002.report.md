# GEN-002 accounting investigation
Read-only source inspection found two accounting defects that matter before a cost comparison: the scanner omits usage that pinned Pi records outside assistant messages, and it reports unknown model prices as zero. The stats command also scans ordinary Pi sessions, so its current totals cannot be described as strictly Takomi-owned. No live logs, requests, probes, benchmarks, or files were changed.
The task packet was found under `in-progress/GEN-002_verify_usage_accounting_and_benchmark_readiness.task.md`, not the requested `pending/GEN-002_accounting.task.md`.

## Recommended Build sequence
1. **Scanner correctness, owned by the accounting builder.** Change `src/takomi-stats.js` and its mirrored `.pi/extensions/takomi-runtime/takomi-stats.js` together. Add canonical-file deduplication and the pinned Pi usage-bearing entry types. Keep session, entry, and usage-kind identities through cache and rollups. Add focused synthetic cases to `scripts/test-regressions.js`; run those and `scripts/test-stats-cache-parity.js`.
2. **Cost completeness and labels.** In the same scanner pair and relevant renderers, preserve known cost estimates while exposing unpriced usage and Antigravity's estimated-token/subscription basis. Update cache serialization/version in `src/takomi-cache.js` and its runtime mirror if cached shapes change. Test fresh-versus-cached outputs, unknown models, and mixed pricing.
3. **Attribution only after format approval.** Use native session headers and entry IDs plus validated subagent launch/completion links. Add no time-based joins. Test parent/child/fork and missing-artifact cases before advertising complete task costs.
4. **Targeted documentation.** Amend the affected claims in `docs/features/Token_Usage_Ledger_Dashboard_Spec.md` and any affected stats/router usage text. Separate shipped behavior, optional filtering, known estimates, and future benchmark plans.
## Decisions requiring approval
- Should `takomi stats` retain its current broad Pi aggregate as a clearly labeled view, or change its default to Takomi-only? The latter changes a documented user-visible contract and needs an agreed ownership signal.
- May the persistent stats cache gain versioned event IDs, usage kinds, missing-price state, and optional parent/child provenance? If yes, define cache invalidation and whether existing historical data is recomputed. Do not modify real logs.
- May future runs persist task/run linkage beyond native Pi entries, and which identifiers may be stored? Keep prompt text, credentials, and provider payloads out of that record.
- What counts as a complete task when a child session, failed request, or usage record is absent? The safe default is "incomplete," with observed subtotals shown separately.
## Benchmark-readiness gate
Before any paid comparison, require passing synthetic source/cache parity tests; an approved task boundary and outcome rubric; visible priced/unpriced and observed/unknown coverage; validated parent-child links; fixed model/provider and tool-capability settings for controlled trials; documented cache conditions and repeated trials; and a separate practical-default comparison. Approval must identify budget and target environment. Until then, no aggregate here is evidence of a full-task cost or a Takomi-versus-Codex efficiency win.
