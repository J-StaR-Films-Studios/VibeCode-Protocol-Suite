# GEN-003 compatibility investigation
This was a read-only source and documentation review of the isolated worktree. The package pins Pi **0.84.4** and `pi-subagents` **0.31.0**; the inspected global Pi package is **0.99.1**. The worktree has no `node_modules`, so I could not inspect the installed 0.84.4 implementation or run its compatibility probe. None of the findings below establishes runtime compatibility on this machine.
I read the installed Pi documentation for extensions, SDK, MCP, compaction, configuration, security, and CLI behavior, plus its extension examples and SDK codemode/MCP example. Those documents describe 0.99.1. They are not an API contract for the pinned release.

## Supported-baseline decision
**Recommended now: keep 0.84.4 as the implementation target.** It matches the exact package and lockfile pins and the private-API manifest. The cost is that 0.99.1 features cannot be assumed available. Prerequisite: make the pinned dependencies available through an approved, reproducible setup, then run `scripts/test-pi-subagents-compatibility.js`, focused subagent lifecycle, trust, and context-manager tests, and typecheck. Confirm the actual pinned extension declarations and provider implementation before accepting API or WebSocket claims. No install was performed in Genesis.
An **approved upgrade track to 0.99.1** could enable native exposure and search and reduce custom work, but it changes Pi, `pi-subagents` peer compatibility, private import paths, the renderer patch, event contracts, and request behavior together. Treat it as a separate migration with a lockfile/manifest update, an adapted compatibility probe, offline RPC registration tests, focused routing and delegation regressions, and an isolated end-to-end launch before changing the supported version. Do not use the active global executable as a substitute for this test.
For source development, invoke the **pinned local CLI once available** with `--no-extensions` and explicit worktree extension paths, following `scripts/pi-dev.ps1` and the offline RPC compatibility probe. Keep session and agent configuration isolated for tests; do not copy personal settings or credentials. The existing PowerShell launcher calls `pi` from `PATH`, so its duplicate-registration isolation does **not** pin the executable version. Record the executable path and version before interpreting a manual result. `--no-extensions` prevents duplicate extension discovery but does not itself remove all other user configuration; use the test probe's explicit `--no-skills`, `--no-context-files`, `--offline`, and in-memory session flags where appropriate.
## Bounded Build handoff
1. **Baseline verification, before behavior changes.** Arrange approved local pinned dependencies, run the offline compatibility probe and relevant existing tests, and record the resolved executable and module versions. Acceptance: the six private imports and renderer patch load under 0.84.4, one explicit extension set registers, and tests report their actual results. A failure is an investigation, not permission for an automatic upgrade.
2. **Compatibility checks only where a change requires them.** If tool exposure or routing changes, inspect the pinned declarations first. Test tool discovery and gates across inactive, loaded, resumed, and child contexts as applicable; test provider request equivalence without a live request. Preserve current admission and trust checks.
3. **Targeted documentation after implementation decisions.** Reconcile FR-002/FR-006 and the context-manager feature document with verified defaults; let GEN-002 settle the stats ownership claim. State the version tested and label Codex plugin packaging separately from execution parity.
The builder should read `package.json`, the compatibility manifest and probe, `pi-subagents-internal.ts`, `pi-subagents-engine.ts`, `tool-runner.ts`, and both source-checkout launch paths first. Installed 0.99.1 docs are useful for comparing options, not for implementing against 0.84.4.
No tests or live requests were run in this investigation. No files, settings, dependencies, plugins, or global resources were changed.
